# CapCut lane: lab notes

**The locks that are true only on this lane.** Moved out of the root `CLAUDE.md` Lab Notes on 2026-09-03 so the universal locks read as universal: every bullet here is CapCut mechanics, none of it is a look decision (those stay in the presets) and none of it is pipeline law (that stays in `CLAUDE.md`). One lock per line, pointing at the doc that owns the mechanics.

- **The lane = `lanes/capcut/capcut-bridge.py`, built + validated 2026-07-27** (CapCut 8.9.0, `com.lemon.lvoverseas`). CapCut has NO API, so the bridge runs two lanes: a **file lane** (writes the plaintext draft JSON, structural and exact, app QUIT) and a **live AX lane** (drives the running app through ByteDance's internal automation IDs, locate → act → verify, no restart). File lane for bulk/structural builds, live lane for interactive edits. Premiere is a separate lane; this one is CapCut. Owner: `.claude/skills/capcut/SKILL.md`.
- **A draft is THREE files in sync** — `draft_info.json` (timeline + a `materials.videos` entry + the six per-segment helper materials CapCut itself writes: speed/placeholder/canvas/channel-map/color/vocal-separation) + `draft_meta_info.json` + a row in the shared `root_meta_info.json` registry — **and CapCut must be QUIT while writing**, because it rewrites that registry on exit and will clobber the new row. Source times are in **microseconds**, `target_timerange` butt-joined (verified 10/10 exact against the intro EDL, zero drift). Owner: `capcut` skill § Procedure 2.
- **The sandbox is the gotcha: CapCut ships `com.apple.security.app-sandbox` with only `assets.movies.read-write`**, so ANY path outside `~/Movies` opens as a red "File not accessible" timeline behind a Link media dialog. The bridge hardlinks the raw into `<draft>/Resources/` (same APFS volume, zero bytes copied) and points the material there.
- **AX ids are internal test hooks, NOT a contract — re-verify with `dump` after any CapCut update.** The transport button's id flips `PlayerPlayBtn` ↔ `PlayerPauseBtn` with state; the window can reposition across displays after launch, so **re-find geometry right before clicking, never cache it**; dialogs (Link media, export) expose only their container, so their buttons need offset clicks; `osascript` quit returns a harmless `-128`.
- **`Timelines/` cache: CapCut imports `draft_info.json` only on a draft's FIRST open**, then builds native state in `<draft>/Timelines/` and trusts that forever — later JSON edits are silently IGNORED. To file-lane-edit an existing draft: quit, rewrite the JSON, and DELETE `Timelines/` + `draft_info.json.bak` to force a re-import. A fresh `replay` is unaffected (no cache exists yet). Owner: `capcut` skill § Lab-Notes locks.
- **Re-adding a RE-RENDERED overlay serves the OLD file, silently (2026-07-30).** `add-overlay` skips the copy into `<draft>/Resources/` when the filename already exists, so a v2 render at the same path never reaches CapCut — and every check passes (segment times, material paths, `clips`, `state` all read correct; only the Resources copy's hash/inode differ). It also strands the segment on the OLD media duration. Fix: `rm <draft>/Resources/<name>.mov` first (breaks the hardlink to the stale inode), re-copy, patch `materials.videos[].duration` + any `source_timerange`/`target_timerange` that now overruns, then wipe `Timelines/`. Use `--force`, or version the filename. **Verify a re-render landed by hashing the Resources copy against the render — never by re-reading the timeline.**
- **Once a draft has been hand-edited in the app, additive-edit the CURRENT `draft_info.json`** (those edits are saved into it on quit) — never regenerate from the EDL; a rebuild clobbered a hand-extended segment on 2026-07-27. `replay` is for a fresh draft only.
- **The draft's frame rate is the FOOTAGE's, set at `replay` (2026-09-27; replaces "import re-quantizes to 30 fps").** CapCut stores it as `fps` + `is_drop_frame_timecode`: 29.97 is the EXACT 30000/1001 with drop-frame ON; a rounded 29.97 without the flag came back 30.0 after CapCut's own save. The old hardcoded 30.0 put every cut of a 29.97 take a frame late and exported at 30. Changing the rate later (Project settings > Modify) keeps each clip's FRAME COUNT, sliding every cut. Export at the timeline's own rate: another rate relabels frames (29.97 off a 30 fps timeline: 31 ms of A/V drift by 32 s).
- **Two export locks. (1) The post-export share screen is MODAL** and blocks the next export — escape before AND after, and **NEVER click through it: it publishes to TikTok/YouTube.** **(2) A `source_timerange: null` on any segment WEDGES the encoder mid-render** (froze at exactly the text segment's 30% mark, twice); CapCut writes null there for text segments internally and it survives a file-lane rewrite, so `edit_draft` backfills every null source range before writing. A wedged export needs `kill -9` (the modal blocks a graceful quit) + a `Timelines/` delete before relaunch. Owner: `capcut` skill § Procedure 8.
- **Only the FIRST export of a CapCut launch completes (8.9.0, live 2026-09-26, reproduced 4 times, with and without the bridge).** A second export renders into the previous export's `~/Downloads/.__capcut_export_temp_folder_*`, never moves the file out, and the dialog freezes at **30.0%** with no null source range anywhere in the draft, so the "30% wedge" below may be this bug too. `export` relaunches CapCut (graceful quit, reopen `--draft`) before a second export from the same process, and its timeout names leftover temp folders; a frozen export is stopped with the dialog's Cancel then the confirm's OK, no kill. Owner: `capcut` skill § Procedure 8.
- **The bridge cannot set the export dialog's Export to; the file lands where the dialog says (~/Downloads by default).** `export --to <dir>` watches both and MOVES a Downloads landing into `<dir>`, never over an existing file (a draft named after the job lands on `outputs/<job>.mp4`, the base cut's name). The codec is the creator's too on macOS: the dialog defaults to HEVC and the H.264 check fails until it is switched (sticky once set). On Windows the bridge picks H.264 itself (a fresh draft's dialog read HEVC on the re-test, 2026-09-27) and delivers through a master (below). Owner: `capcut` skill § Procedure 8.
- **Launch dialogs ("CapCut Ultra is live" and the like) are modal AXDialog windows that eat the tile double-click (8.9.0, 2026-09-26, 3 launches of 4).** `open` closes each through its own title-bar close button, never a button inside it ("Install now" updates the app, "Turn on" subscribes). Every file-lane command reopens through `open`, so all of them depended on this.
- **The Media panel lists `draft_meta_info.json`'s type-0 `draft_materials`, one row per imported file;** a raw missing there plays on the timeline but is absent from the bin. `replay` writes one row per raw (regression: `workflows/test_capcut_replay.py`).
- **Never force-kill CapCut to restart or unstick it.** Quit it gracefully, or hand it back to the creator; the one exception is the wedged export above (`kill -9` + the `Timelines/` delete), where the modal blocks a graceful quit.
- **CapCut composites ProRes 4444 alpha as PREMULTIPLIED; hyperframes renders STRAIGHT.** Solid glyphs look fine, which is why the drop-test missed it, but every semi-transparent pixel (motion blur, glows, soft shadows, fades) blows out toward white. Premultiply every CapCut-bound alpha mov first; Premiere and Resolve both assume STRAIGHT, so never premultiply for either. Full rule: `capcut` skill § Procedure 4.
- **Tell straight from premultiplied by sampling one semi-transparent pixel:** RGB holding its full value as alpha drops = straight; RGB scaling down with alpha = premultiplied.
- **The converter is this lane's own script: `bash lanes/capcut/premultiply.sh <in.mov> [out.mov]`** (default output `<in>-premult.mov` beside the input; it prints the path it wrote). The preset builders render STRAIGHT alpha and know nothing about CapCut — the conversion belongs here, run it before `add-overlay`.
- **Background removal IS drivable live, and it is CapCut's own AI matte (Pro), validated 2026-07-27:** select the clip → `click "VESettingPanelSubTabControl:Remove BG"` → offset-click the Auto removal checkbox at the LEFT edge of `automationaiMattingGroup` (the row exposes no AX child). It writes `matting.flag: 3` + a mask cache in `<draft>/matting/<hash>/` keyed on the MEDIA; flag 0 = off, 1 = requested-not-applied, 3 = live. **QA trap that ate an hour:** the cutout layer is the same footage as the main track, so until the matte lands it covers the frame and every layer under it reads as "not rendering" — verify `matting.flag == 3`, or `delete` the top clip, before debugging anything below it. Owner: `capcut` skill § Procedure 5.
- **Z-order is TRACK stacking, not segment `render_index`.** `render_index` only orders within a track; `track_render_index` + the tracks-array order composite, and **a text track can NEVER go below a video layer** (out-of-band values like ri 15000 just look like they worked). Type that must sit *behind* a subject gets baked to an alpha ProRes overlay, not a CapCut text track. The stack for text-behind-subject: main → black clip (its `clip.alpha` IS the background-darkness knob) → title mov → muted duplicate of the same footage with the matte on (unmuted it doubles the voice).
- **Motion keyframes are fully file-lane writable** (`common_keyframes` on the segment, one entry per `property_type`), so zooms/pushes/moves have Premiere's expressive range and land more exactly. ⚠️ **`time_offset` is in the SOURCE time domain, not segment-relative, and getting it wrong fails SILENTLY** — the animation collapses to one static value. Verify by parking the playhead BETWEEN two keyframes and reading the inspector, never off program-monitor frames. Only `curveType: "Line"` is verified; stack extra keyframes rather than guessing an ease name. Owner: `capcut` skill § Procedure 6.
- **Coach-marks swallow clicks and are INVISIBLE to the AX tree (2026-07-27, cost half an hour).** `dump` looks clean, every live command reports success, and nothing happens in that screen region. **Rule: when a live action reports success but state didn't change, `shot` the window and look for a yellow bubble** (dismiss with an offset click on its OK); take a `shot` at the top of any live session. Three companion live-lane traps: the ruler's ~90 px dead strip at its left edge eats clicks, frame steps must be PACED (195 sent, 28 applied), and synthesized input only lands when CapCut is frontmost.
- **CapCut earrape audio on a MOV that plays fine in QuickTime/Premiere (2026-07-28):** a QuickTime Player Maximum-quality recording writes 32-bit big-endian PCM that ffmpeg-lineage parsers (and CapCut's importer) misframe as 24-bit, decoding as full-scale static — the source is NOT broken. Diagnose in seconds: per-second RMS dead-flat around −8 dB = misframed PCM, not hot audio. Fix at intake with `afconvert -f WAVE -d LEI24@48000 <raw.mov> audio.wav`, then remux against the original video. **Never swap media files under an existing draft** — the bridge's `quit` races CapCut's async shutdown save and zeroed a `draft_info.json`; with no hand edits, delete the draft + registry row and `replay` fresh.
- **`graphics` creates overlay layers lowest first, on every OS (2026-09-27)**: `overlay_track()` numbers layers by creation order, and a caption row created first became layer 1, so CapCut pushed every later graphic past its end (a 55 s timeline).

## Windows (CapCut for Windows, Qt 6.2; proven 2026-09-27)

- **No accessibility tree below the top-level windows** (UIA: `HomeWindow`, `MainWindow`, splash/update dialogs; no QML children, no MSAA). The Windows live lane is `lanes/capcut/capcut_win.py`: the app's own shortcuts + RapidOCR read-back + clicks at OCR-fitted positions. Windows' own OCR (Windows.Media.Ocr) never read the player timecode; RapidOCR did at 0.97.
- **Shortcuts are the ACTIVE keymap's** (`Config/keymapSettings currentKeymapIndex`; 0 = built-in: split Ctrl+B, export Ctrl+E, the shipped `Final Cut Pro X.json`'s bindings). Custom1's Ctrl+K split nothing. Key events go one per SendInput with scan codes, spaced: a modifier and key in one batch reached CapCut as the bare key.
- **In-editor toasts swallow clicks** (shortcut-conflict, EditPilot tour, "Auto optimization is on"): painted inside `MainWindow`, invisible to UIA; `dismiss_tips()` OCRs the lower-right and closes them.
- **RapidOCR's detector UPSCALES small crops** to a 736 px short side by default (2 s for a 254x39 strip): construct it with `det_limit_type="max"`, and skip the angle classifier.
- **A 29.97 draft's readouts are drop-frame** (`00:00:32;10`, ruler labels `00:01:00;02`): convert with the DF formula, never `s + f/fps`, past the first minute.
- **Positions**: `clip.transform` runs over the HALF canvas (±1 = an edge) and +y is UP (measured: y -0.5 moved the picture down a quarter frame).
- **Export**: default folder `%LOCALAPPDATA%\CapCut\Videos` (in no config file); the dialog and the share screen are painted in the editor; the share screen holds the file open ("resource busy") and blocks the export shortcut; an overwritten export keeps its old mtime. Close the share screen by the Close beside Share, never Share.
- **The deliverable is encoded from a MASTER, not taken from the dialog (your call, 2026-09-27; proven 2026-09-28).** The dialog has no profile or audio-bitrate control and its Recommended bit rate landed H.264 Main, 10.0 Mbps, AAC 197 kb/s at 1080×1920. So the bridge sets Bit rate = Custom at 50,000 Kbps (the field clamps there: 60,000 typed read back 50,000) and ticks the Audio section (below the fold: wheel the settings panel; a ticked box is drawn in the accent colour) with Format = WAV; `workflows/deliver.py` encodes H.264 High / CBR 14 / AAC 320k 48 kHz from the pair. With Audio ticked CapCut writes BOTH files into a folder named after the export, `<Export to>\<name>\<name>.mp4` + `<name>.WAV` (44.1 kHz, 16-bit), and holds the mp4 open for a few seconds after (the rename retries for 30 s). The bridge proves the audio by its 48 kHz, never the measured rate: ffmpeg's AAC asked for 320k spends 246–263 kb/s on a dual-mono voice (R11).
- **A short draft renders in seconds, and CapCut shows the export dialog AGAIN afterwards;** a click counted by "the dialog is gone" clicked Export twice and met **"File already exists … replace it?"**. The click is taken when the export's own file changes; that question is never answered OK (its Cancel, the dialog's Cancel, exit naming the file); the re-shown dialog is cancelled after the render.
- **The first-export-per-launch bug holds on Windows too (2026-09-28):** a second export in one launch froze at 30%. Stop it with the Exporting screen's Cancel (beside "Back to home"), then OK on "Stop exporting your video?", picked by its position under the question: the first OCR'd "OK" was a tooltip's. The bridge records the exporting process id (in `%TEMP%`) and relaunches before the next export.
- **Quit**: WM_CLOSE on the editor lands on the Home window, which needs its own close.
- **Text templates** from macOS carry `/Users/.../Cache/effect/...` font and animation paths; CapCut re-resolves both by resource id and rewrites them to the local cache on open.
