# Resolve lane: lab notes

**The locks that are true only on this lane.** Moved out of the root `CLAUDE.md` Lab Notes on 2026-09-03 so the universal locks read as universal: every bullet here is Resolve mechanics, none of it is a look decision (those stay in the presets) and none of it is pipeline law (that stays in `CLAUDE.md`). One lock per line, pointing at the doc that owns the mechanics.

- **Let Resolve conform mismatched resolution; NEVER hand-scale (2026-08-05).** `timelineInputResMismatchBehavior` defaults to `scaleToFit`, so a 1080p asset already fills a 4K frame — the Premiere Motion Scale 200 habit doubles it to 400% and crops plausibly enough to ship. Leave `ZoomX`/`ZoomY` at 1.0 and verify from a render; a clip-level readback reports the zoom it was told and hides the crop. Same conform makes mixed fps land frame-for-frame, so frame-indexed graphics keep their positions. Owner: `davinci-resolve` skill § Vertical (9:16) framing.
- **Graphics lane validated 2026-08-05** (9 alpha overlays on V2, verified by render): ProRes 4444 drops in with **zero alpha config — Resolve auto-detects `Alpha mode: Straight`**, never premultiply here. `TimelineItem` has no keyframe API, so an animated footage move is a Fusion `Transform` comp on the clip — `add_keyframe` on `Size` verified interpolating (1.0→1.07 reads 1.035 mid-clip). Script the placement per job, idempotent and readback-verified. Mechanics: `davinci-resolve` skill § Step 5.
- **Grading = a COLOR GROUP + ONE DCTL, validated 2026-08-06** (9 clips, one shader, verified by render). A colour group IS Resolve's adjustment layer and it is fully scriptable off `project`; `Graph` has no `AddNode`, so the whole look goes in one node, which means a DCTL. **Probing leaves grades behind** — a failed DCTL passes through, so sweep every level (pre-clip, post-clip, item) on teardown. Owner: [`lanes/resolve/resolve-grading/README.md`](../../lanes/resolve/resolve-grading/README.md).
- **Step-3 audio polish = ffmpeg on each SOURCE FILE + `MediaPoolItem.ReplaceClip`, validated 2026-08-06** (9 sections, 210 clips, section spread 4.7 → 1.1 LU, zero clips moved). The API has no audio-gain surface at all, so the lane swaps media instead of applying effects; verify zero timing drift before committing, and re-run the pass after any timeline rebuild. Owner: [`lanes/resolve/resolve-audio-polish/README.md`](../../lanes/resolve/resolve-audio-polish/README.md).
- **Resolve delivery render = [`lanes/resolve/resolve-export.md`](../../lanes/resolve/resolve-export.md), measured 2026-08-06.** `VideoQuality` is a dropdown INDEX, not a bitrate (50000 is silently ignored; 100 gives 1.1 Mbps); `MultiPassEncode` is the only real quality lever (18.8 → 36.8 Mbps measured); a multi-pass render looks FROZEN at a tiny file size while working fine; `GetRenderSettings` is not callable, so verify with ffprobe on the finished file. The Premiere CBR-50 lock does NOT port to Resolve; chasing that number already cost one wasted render.
- **Resolve 21.1 ships an OFFICIAL MCP server, proven end to end 2026-09-25** (`your-job-resolve`: a delivered Premiere short rebuilt from its .prproj, PSNR 42.9 dB mean against the Premiere master over all 2872 frames). Binary `DaVinci Resolve.app/Contents/Applications/ResolveMCP` (stdio; the `davinci-resolve` server on the author's machine since 2026-09-25, while `setup-resolve.sh` still installs the community engine for clients: `davinci-resolve` skill § Wiring), 14 tools, the workhorse is `run_script` = sandboxed Python with `resolve`/`project` bound, **60 s hard cap per call**. What 21.1 changed against the notes above: `VideoQuality: <int>` IS a bitrate in kb/s now (14000 → 13.96 Mbps); clip `AudioVolume` (dB) and `SetFades` exist (still no limiter/EQ, so the step-3 bake stays); `generate_lut` is sandboxed (no `open`), so a transform of an existing cube carries the cube inline. Unchanged: playback fps is unwritable (template still required). New trap: `SaveProject()` on "Untitled Project" opens a name dialog and hangs the script. Record: that job's RUN.md.
- **Resolve lane wired 2026-08-03:** `davinci-resolve` MCP in `.mcp.json` (machine-local, same pattern as premiere-pro) → pinned gitignored clone at `vendor/davinci-resolve-mcp/` (`samuelgursky/davinci-resolve-mcp` v2.72.0, commit `a9fd831`, update checks set to never — bump the pin deliberately). Compound server (`src/server.py`, 34 grouped tools; `--full` = 341 granular), venv built by `python3 install.py --clients manual`. Talks to the OFFICIAL scripting API — needs External scripting = Local (Resolve's shipped default) and the three env vars in `.mcp.json`; no bridge panel, but Resolve must be RUNNING. Smoke-tested live over stdio against Resolve Studio 21.0.3.7.
- **Free edition = the in-app bridge, decided by the installer (2026-09-07).** External scripting is Studio-only, and on Windows the free edition's `scriptapp("Resolve")` HANGS rather than refusing, so a free lane wired the Studio way sat on its first call for Claude Code's 30-minute idle timeout. `setup-resolve.sh` detects the edition (`.license/.davinciresolvestudio_*`, the Windows uninstall `DisplayName`, the App Store Studio bundle; nothing saying Studio means the bridge, `--studio`/`--free` override), runs the vendored `install_resolve_bridge.py`, seeds the project root into the bridge's allow-lists (its default output root is `~/Movies`), and bakes `DAVINCI_RESOLVE_BRIDGE=1` into the venv as a `.pth`: a flag added to `.mcp.json`'s `env` mid-session never reaches a server Claude Code respawns from its session-start snapshot. Per Resolve session the user runs Workspace → Scripts → resolve_bridge; `BRIDGE_UNAVAILABLE` = not started, never retry in a loop. The entry carries `"timeout": 600000`.
- **EDL replay is ONE call, validated 2026-08-03:** `media_pool create_timeline_from_clips` in SOURCE frames at the fps Resolve ingested the clip at, `end_frame` EXCLUSIVE, `record_frame` timeline-relative; then `project_manager save` immediately (GUI + unsaved = a modal no script can dismiss). Shape, the readback offsets and the conform-by-time result: `davinci-resolve` skill § Step 2.
- **MATCH THE PROJECT TO THE SOURCE FPS AND BUILD IT FROM A TEMPLATE `.drp` — never `create_project` + `set_setting` (2026-08-04).** `timelinePlaybackFrameRate` is unwritable by the API and a 30 fps timeline left at 24 playback = chopped audio; `ImportProject` of a template carries fps + resolution wholesale. **Never solve this by driving the UI** — UI automation is banned here; the API path is the required route (2026-08-04). One template per rate, minting is scripted. Owner: [`lanes/resolve/resolve-templates/README.md`](../../lanes/resolve/resolve-templates/README.md).
- **An iPhone take ingests at 30.00 while its nominal rate is 29.97: `SetClipProperty('FPS', '29.97')` after import puts it back (iPhone VFR trap, 2026-08-13; fixed 2026-09-27).** Before the fix the lane built the project at Resolve's 30.00 so the cuts landed, which left a Resolve finish on a different frame grid from the plan, the renders and Premiere (a 195-frame graphic ended a frame early, the Windows lane test). The property takes on 21.1 and keeps the clip's frame count; a timeline from the same EDL rendered every frame onto the raw frame Premiere's export shows (macOS, 159 of 159). **But the picture keeps the NATIVE time base (the Windows re-test, 2026-09-27):** source frame f still decodes at f / 30.0, so a V1 laid at `round(start x 29.97)` drifted behind its own sound through a long take (3-4 frames at 127 s of a 150 s iPhone take; the 10.7 s Mac clip hid it). Read the FPS before setting it, lay V1 from `round(start x native)`, A1 from `round(start x nominal)`, and run each V1 item at native/nominal speed (100.1%, nearest retime, no ripple): without the speed a single long segment still slid 0 → −2 frames over 60 s (macOS), with it every segment sits within one frame of the splice and keeps its exact duration. Owner: `davinci-resolve` § Project setup, § Step 2.
- **Keyboard = the stock Adobe Premiere Pro keymap preset.** Resolve ships official Premiere/FCP/Avid/Pro Tools keymaps and was ALREADY on the Adobe Premiere Pro one — never hand-transfer the factory Premiere map. Only personal key overrides need porting (left-hand cluster: A/S edits, E/R frames, V blade, Delete ripple-delete, Z zoom, X/C nudge, L link); presets are plain editable text (export → edit → import), never hand-clicked; the one-off port script and its output were deleted from the repo 2026-09-04 (git history before `9d6f807`), the preset lives in Resolve. Verify functionally: the per-key badge on the virtual keyboard lies.
- **UI layout = the "Premiere" layout preset (2026-08-03): Media Pool top-left, Effects Library bottom-left, Inspector right, tall audio waveforms.** The API's entire UI surface is page switching + `layout_presets` save/load/export/import, and the export is an opaque 88 KB Qt blob — not authorable, only captured. Arrange once by hand, save, and it is one MCP call to restore forever. (The captured layout blob and your Premiere-keymap port were deleted from the repo 2026-09-04 as one-off personal setup; git history before `9d6f807` holds them, and Resolve keeps the saved preset itself.)
